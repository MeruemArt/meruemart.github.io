Instalación descargando imagen base

Este artículo aplica para la arquitectura Serverless (Nube)

A continuación se detalla el paso a paso que se debe realizar para instalar locamente la imagen base, partiendo desde sus prerrequisitos, ubicación, descarga, configuración de archivos y variables locales para levantar correctamente el contenedor.

1. Identificar el nombre y la ubicación de la imagen base

Con el objetivo de validar la versión de la imagen base del cwc o de la imagen base con productos, se debe recurrir al archivo spec.json que se encuentra desplegado según la rama del ambiente correspondiente (develop, quality, staging, master), en el repositorio XXXXX-cloud-infra-cwc, donde XXXXX corresponde a las iniciales del cliente por ejemplo: cobis-cloud-infra-cwc, saf-cloud-infra-cwc, rap-cloud-infra-cwc, clf-cloud-infra-cwc, entre otros.

Captura del archivo spec.json

El imageId hace referencia a la imagen base y el imageTag hace referencia al nombre de la imagen base con productos o también llamada imagen con módulos.

Si se necesita conocer la ruta exacta donde está almacenada la imagen base con productos se puede acceder:

  • Clic aquí para acceder a la Ruta del pipeline

  • Clic en la primera ejecución

  • Clic en primary deploy

  • Nos situamos en la task Tag docker image y obtendremos el imageTag

2. Descargar la imagen base

La imagen base se puede descargar de dos formas, ya sea a través de Docker Desktop (paso 2.1) o a través de Docker Compose (paso 2.2).

Proceso de login

  • Proceso de login en la cuenta de AWS

  • Ingresar a la cuenta de AWS COBIS SHARED SERVICES después en la zona de virginia buscar en ECR (Elastic Container Registry), el repositorio cobis/infrafrontend.

  • En el repo cobis/infrafrontend comprobar que se encuentra la imagen base que se desea descargar. En este ejemplo la imagen base que se utilizó fue: base-cobisweb-2.59.0

aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 125277160564.dkr.ecr.us-east-1.amazonaws.com

  • El anterior comando se obtuvo de la opción ver comandos de envío

  • Ejecutamos el comando login

2.1 Descargar la imagen base con Docker Desktop

Descripción

Docker Desktop

Instalar Docker Desktop

Tener instalado Docker Desktop. En caso de no tenerlo instalado, puede seguir el punto 2 de esta guía de instalación

  • Iniciar Docker Desktop e ingresar al powershell y seguir los siguientes pasos:

Descargar la imagen base con Docker Desktop

Notese que el comando indica la imagen que usaremos que es la:

base-cobisweb-2.59.0

  1. Después se procede a descargar la imagen Docker con el siguiente comando:

    2. docker pull 125277160564.dkr.ecr.us-east-1.amazonaws.com/cobis/infrafrontend:base-cobisweb-2.59.0

  3. Una vez se descarga la imagen base se procede a validar su descarga a través del comando docker images que permite listar todas las imágenes base que han sido descargadas.

    docker images

  4. Para copiar la imagen Docker lo primero que se debe realizar es correr la imagen en la aplicación Docker Desktop.

  5. Después crear una carpeta donde se vaya a guardar la imagen base

    mkdir ImagenBase cd ImagenBase

  6. En esa ruta ejecutar el siguiente comando:

    docker ps

  7. Copiar el id del contenedor y reemplazarlo utilizando la siguiente estructura::

    docker cp $id_contenedor:/home/cobisuser/cobishome-web C:\ImagenBase
    docker cp 9b741c882c5b:/home/cobisuser/cobishome-web C:\ImagenBase

  8. Después de ejecutar el comando se observa que la imagen se descargó correctamente de forma local.

2. 2. Descargar la imagen base con Docker Compose

Recurso

Descripción

docker-compose-image

Archivo docker-compose-image que permite descargar tanto la imagen base como la imagen base con productos sin necesidad de instalar Docker Desktop.

git bash

Tener instalado git bash

Descargar la imagen base con Docker Compose

  1. Una vez se descarga el archivo se procede a validar que las credenciales de la cuenta de aws se encuentren actualizadas.

  2. En el archivo .env validar que la cuenta de aws, el nombre de la imagen base y la ruta definida como salida sea correcta.

    La ruta definida en la propiedad TARGET puede cambiar y ser nombrada diferente a elección personal.

  3. En el archivo start.sh validar que el response corresponda a la región y a la cuenta de aws que pertenece la imagen base.

  4. Después de haber validado los puntos anteriores se procede a ejecutar el siguiente comando en una consola bash.

    sh start.sh

    Captura de la ejecución del comando

  5. Por último, se observa que la imagen se descargó correctamente en la ruta local que se definió inicialmente.

3. Modificar la configuración del log

El contenedor web de la imagen, está configurado para registrar los logs en consola, si desea que registre logs en archivos, debe utilizar el archivo cwc-log-config.xml (que se encuentra en la tabla inferior), y reemplazarlo en la ruta cobishome-web\cwc\infrastructure de su cobishome-web descargado localmente.

Recurso

Descripción

Archivo cwc-log-config.xml

Recurso que permite registrar los logs.

4. Verificar las licencias

Se procede a validar la licencia para ello se debe ingresar a la carpeta de la imagen base, después a la carpeta cwc\license y verificar que se encuentran agregados los archivos de la licencia: cwc.lic (licencia del CWC) y designerFra.lic (licencia de Designer Framework).

En caso de no tener los archivos correspondientes se debe generar un caso redmine al equipo ACO solicitando dichas licencias y adjuntando el archivo requester

5. Configurar las variables de ambiente y de sistema

En el transcurso de la instalación del contenedor mediante la imagen base, el archivo cobis-container-config.xml que se encuentra en la ruta: cobishome-web\cwc\services-as\cobis-container queda con variables de ambiente y de sistema, por lo que las variables deben ser reemplazadas tal y como se indica en el siguiente documento: Configuración de variables de ambiente y del sistema

Las variables son diferentes en cada imagen base y siempre será necesario validar que se encuentren configuradas ya sea en el setenv.bat o directamente con el valor definido como se indica en el siguiente documento: Configuración de variables de ambiente y del sistema.

En caso de existir una variable de ambiente o de sistema en estos archivos que no se encuentre definida en el archivo setenv.bat la ejecución del contenedor fallará.
